# 律师模拟器 · 游戏设计文档（GDD）

> 状态：设计草案 v0.1（2026-08-14）
> 本文是项目设计的唯一权威文档，所有系统设计以本文为准；设计变更需先更新本文。

---

## 1. 游戏概述

- **游戏名称**：律师模拟器（暂定，最终名称待定）
- **游戏类型**：2D 职场模拟 + 卡牌庭审 + 多结局文字冒险
- **目标平台**：Steam（PC）
- **目标时长**：单周目约 5 小时达成好结局；全结局收集约 8~10 小时
- **核心体验**：扮演刚毕业的法学生，从实习律师开始成长，在"案件、职场、道德"的三重压力下做出选择，最终由数值清算出结局
- **一句话描述**：你以为你在维护正义，其实你只是在攒卡、攒口碑、攒良知——或者攒违法值。

## 2. 核心循环

```mermaid
flowchart LR
  A[新的一周] --> B[选择行动/日常任务]
  B --> C[获得卡牌/遗物/数值变化]
  C --> D[办公室组牌备战]
  D --> E[庭审卡牌战]
  E --> F[心证结算/数值变化]
  F --> G{章节终点?}
  G -->|否| A
  G -->|是| H[考核/转正/方向选择]
  H --> I[结局结算]
```

- **产出端**：日常任务 → 卡牌、遗物、数值
- **消耗端**：庭审卡牌战（单场 Boss 战，非爬塔）
- **反馈端**：数值与心证 → 章节节点 → 结局

## 3. 时间与回合

- 以"周"为回合。每周有若干行动点（由精力决定），每项行动/任务消耗行动点。
- 行动类型：工作、学习、社交、休息、日常任务。
- 每章约 65~75 分钟：主线案件 6~8 个事件 + 日常事件 8~10 个 + 1 场庭审 + 章节考核。
- 时间轴：毕业 → 实习期（约 1 年）→ 执业初期 → 资深律师 → 终局结算。

## 4. 数值系统

### 4.1 核心属性

| 属性 | 含义 | 主要影响 |
|---|---|---|
| 专业 | 法律知识、实务能力 | 卡牌效果、庭审选项、法条卡强度 |
| 口碑 | 客户与同行评价 | 案源数量、结局、日常任务解锁 |
| 人际 | 带教律师/同事/法官/当事人关系 | 人物任务链、主线案件分配 |
| 财富 | 收入 | 买书/抽卡包、生活质量 |
| 精力 | 行动资源 | 每周行动次数上限 |
| 良知（隐藏） | 道德立场 | 法官初始心证、公益线结局 |

### 4.2 违法值（风声等级）

- 半隐藏数值，显示为模糊的"风声等级"：平静 / 有闲话 / 被盯上 / 在逃边缘。
- **来源**：勾兑法官、伪造证据、收买证人、威胁当事人、违规收费、隐瞒利益冲突。
- **分层效果**：
  - 低（1~2 点）：仅文本暗示。
  - 中（3~4 点）：任务/庭审难度微增；灰色客户出现，提供高报酬任务与强力卡牌（诱惑滚雪球）。
  - 高（5~6 点）：触发纪检约谈事件；部分清白当事人与法官疏远你。
  - 极高（7 点以上）：随时可能"东窗事发"，进入入狱坏结局。
- **降低途径**：公益任务、律协处分、主动退赃（高风险高回报）。不做随时间自动衰减。

### 4.3 设计原则

- 每个事件至少影响 2 个维度，制造两难选择。
- 勾兑选项的当期收益必须明显强于正道，但代价非线性上升（第 4 点后每点风险翻倍）。
- 良知完全隐藏，违法值半隐藏，玩家只能凭行为估算。

## 5. 日常任务系统

### 5.1 设计原则

- 一个日常人物 = 一条任务链（3~4 个任务变体），好感度提升解锁更深任务与专属卡牌。
- 奖励分两层：数值 + 卡牌/遗物。
- 日常任务反哺主线：主线案件的证据、法条、人脉只能通过对应类型任务获得。
- 精力是硬约束：每周必须选择"做谁的日常"。

### 5.2 日常人物与任务

| 人物 | 日常任务 | 数值奖励 | 卡牌/道具 | 主线联动 |
|---|---|---|---|---|
| 带教律师 | 写检索报告、整理卷宗、庭前准备 | 专业+ | 「庭审节奏」 | 好感 3 级推荐进正当防卫案 |
| 法律援助中心 | 值班咨询、代拟文书、社区普法 | 口碑+、专业+ | 「公益证明」 | 累计 3 次解锁法援大案 |
| 行政前台 | 盖章跑腿、订票、年会筹备 | 人际+ | 「内部消息」 | 透露律所派系，影响晋升线 |
| 同期实习生 | 文书互改、模拟法庭对练 | 专业+、人际+ | 「辩论技巧」 | 组队辩论赛，赢取名声 |
| 合伙人 | 商务应酬、投标材料、出差随行 | 人际+、财富+（精力-） | 「客户名片」 | 好感高才分配证券大案 |
| 老律师前辈 | 喝茶聊天、整理旧案卷 | 良知+、专业+ | 「冷门判例」 | 好感 2 级给旧卷宗，触发申诉线 |
| 法官/书记员 | 立案跑腿、送材料、旁听庭审 | 专业+、人际+ | 「法官视角」 | 降低庭审难度 |
| 媒体记者 | 采访、写普法文章 | 口碑+（有风险） | 「舆论热度」（双刃剑） | 触发舆论事件 |
| 当事人 | 调解、回访、谈判 | 财富+、口碑+ | 「和解协议」 | 奇葩当事人支线 |
| 大学同学 | 聚会、改简历、情报交换 | 人际+ | —（解锁职业选项） | 考公/法务/大所三条线 |
| 家人 | 回家吃饭、体检、相亲 | 精力+（财富-） | 「家的温暖」 | 家庭线数值，防"工作机器"玩法 |
| 书店老板/教授 | 买书、旁听讲座 | 专业+ | 买书=抽卡包 | 卡牌图鉴收集来源 |
| 健身教练 | 健身、体检 | 精力上限+ | —（永久成长） | 防止精力崩盘 |

## 6. 卡牌系统

### 6.1 卡牌分类与出牌阶段

| 卡牌类别 | 可出牌阶段 | 作用 | 来源示例 |
|---|---|---|---|
| 程序卡 | 开庭准备 + 全阶段可用 | 防御、拉心证 | 法援任务、合规任务 |
| 发问卡 | 法庭调查 | 攻击对方证人/当事人 | 调查类任务 |
| 证据卡 | 法庭调查 | 主力攻击/防御 | 走访、查档、证据任务 |
| 质证卡 | 法庭调查 | 反击对方证据 | 旁听、质证练习 |
| 法条卡 | 法庭辩论 | 强力 buff / 大伤害 | 学习、买书 |
| 辩论卡 | 法庭辩论 | 主要输出 | 模拟法庭、辩论赛 |
| 陈述卡 | 最后陈述 | 心证大幅摇摆、终结技 | 特殊事件 |
| 调解卡 | 调解阶段（民事） | 和解胜利 | 当事人任务 |

- 卡牌带阶段标签，只能在对应阶段打出。
- 程序卡是"万能卡"例外：任何阶段可出，但效果按阶段打折。

### 6.2 消耗分层

- **非消耗卡**：质证技巧、程序抗辩、常见法条——本场循环使用，代表可重复的执业能力。
- **本场消耗卡**：关键证据、证人证言、舆论热度——打出后本场移除，代表一次性资源。
- **永久消耗卡**（稀有）：当事人亲笔认罪书等——用一次即从卡组永久消失，可能改变案件走向。

### 6.3 流派（Build 骨架）

| 流派 | 核心机制 | 代表性组合 |
|---|---|---|
| 证据链流 | 证据卡互相触发，越多越强 | 3 张同案证据 → 下张质证卡免费且翻倍 |
| 程序控制流 | 拉心证 + 消耗对方回合 | 回避申请 + 异议连续打断 |
| 舆论爆发流 | 一次性高输出 + 风险 | 媒体直播 + 舆论热度连击，口碑/违法值代价 |
| 辩论连击流 | 法条卡触发辩论卡连锁 | 刑法第二十条 → 下张辩论卡伤害+3 |
| 勾兑流 | 高风险高收益 | 法官是同学 + 红包：本场压制，违法值暴涨 |

- 每张卡带流派标签；遗物和任务也带流派加成。
- 流派克制环：程序控制 → 证据链 → 舆论 → 程序控制。
- Boss 有流派抗性（见 7.4），逼玩家为不同案件准备不同卡组。

### 6.4 伏笔机制（跨阶段组合）

- 法庭调查阶段部分证据卡不立即结算，留下"伏笔标记"。
- 法庭辩论阶段带"引爆"关键词的卡消耗伏笔，获得巨额加成。
- 例：「关键转账记录」（调查阶段留伏笔）→「举证质证」（辩论阶段引爆：对方护甲清零）。

### 6.5 超脱现实的游戏化卡牌（少量）

- **我的回合**（0 费稀有）：打出后本阶段额外获得一个回合。
- **全场安静**：法官敲槌，对方下回合无法行动。
- **时间管理大师**：本阶段抽牌上限 +3。
- **卷宗如山**：把卷宗叠成护甲。
- **灵光一现**：弃光手牌，从牌库指定抽一张核心卡。
- **社会性死亡**：移除对方一张手牌。

> 此类卡每章 2~3 张，作为打破常规的爽点，与严谨流程卡形成节奏反差。

## 7. 庭审战斗系统

### 7.1 五阶段流程（参照真实法庭环节）

```mermaid
flowchart LR
  A[开庭准备<br>核对身份/回避] --> B[法庭调查<br>陈述/举证/质证/发问]
  B --> C[法庭辩论<br>多轮交锋]
  C --> D[最后陈述]
  D --> E[调解或宣判]
```

1. **开庭准备**：宣布纪律、核对身份、询问回避申请（可赌一把换心证）。
2. **法庭调查**：陈述 → 举证质证 → 证人出庭、相互发问。
3. **法庭辩论**：围绕争议焦点多轮交锋。
4. **最后陈述**：终局发言，直接撼动法官心证。
5. **调解/宣判**：民事可先进入调解（另一种胜利方式），谈不拢再宣判；刑事直接宣判。

### 7.2 回合节奏

- 每阶段 2~3 回合；回合内顺序：出牌 → 对方行动 → 法官效果。
- 阶段结束时手中未出的牌清空重抽，每个阶段有独立决策空间。

### 7.3 法官第三方与心证条

- 法官不做敌人也不做友军，是一条**心证条（0~100）+ 每回合环境效果**。
- 开局心证由良心值、程序合规记录、违法值决定。
- 每回合法官敲一次法槌，按心证条给出全场效果（采信倾向 / 程序警告 / 举证压力）。
- 心证是双资源：保留到宣判影响胜负与结局，也可当场消费发动强力效果（如"恳请法庭采纳"）。
- 对方出伪证被抓包时，心证大幅倒向玩家——诱导对方犯错成为战术。

### 7.4 Boss 设计

- **检察官**（刑事）：指控（攻击）→ 结案陈词（AOE）→ 量刑建议（必杀）。
- **对方当事人**（民事）：狡辩（护甲）→ 撒泼（攻击 + debuff）→ 上诉威胁。
- 难度分级（简易/普通/疑难）影响 Boss 强度与法官初始心证。
- 章节最终副本 = 该章知名案件改编（见第 8 节）。

## 8. 章节结构

| 章节 | 时间线 | 原型案件（改编） | 法律焦点 | 核心矛盾 | 章节节点 |
|---|---|---|---|---|---|
| 序章 | 毕业季 | 法考放榜 | 教学关 | 择业：律所/考公/法务 | 进入律所 |
| 第一章 沉睡的法条 | 实习期 | 正当防卫案（于欢案、昆山反杀案启发） | 正当防卫 | 舆论压力 vs 专业判断，会见难 | 实习考核/转正 |
| 第二章 为被告辩护 | 执业初期 | 过失致人死亡案（货拉拉案启发） | 因果关系 | 为"舆论讨厌的人"辩护，案源焦虑 | 独立执业 |
| 第三章 漫长的申诉 | 执业中期 | 申诉再审案（张玉环案、聂树斌案启发） | 疑罪从无 | 数年坚持、阅卷受阻、家属委托 | 专业方向选择 |
| 第四章 千亿的诱惑 | 资深律师 | 证券虚假陈述集体诉讼（康美案启发） | 连带责任 | 当事人利诱 vs 良知 | 合伙人遴选 |
| 终章 | 结算 | — | — | 数值清算 | 结局 |

**可选扩展案件池**（支线/后续章节）：著作权灰色地带（人人影视案）、反垄断（知网案）、未成年人犯罪、寻衅滋事（唐山打人案启发）。

**改编声明**：所有案件保留法律争议内核，全部换名换地换细节，禁止出现真实当事人可识别信息。游戏内注明"案件均为虚构"。

## 9. 结局设计

### 9.1 主要结局

1. 律所合伙人（专业 + 口碑高）
2. 金牌诉讼律师（专业 + 财富高）
3. 公益律师（良知 + 口碑高）
4. 企业法务 / 考公转行（中庸或财富低）
5. 黑心律师（财富高 + 良知低，中途可能被吊销执照）
6. 健康崩溃 / 躺平（精力崩盘）
7. 入狱（违法值满或纪检约谈失败，中途坏结局）

### 9.2 收集与重玩

- 结局图鉴：每解锁一个结局获得收集奖励。
- 新周目（New Game+）：继承图鉴，解锁隐藏事件与卡牌。

## 10. 美术与音频

- **风格**：吉卜力氛围（手绘水彩、暖棕/天空蓝/奶油白），不临摹具体作品。
- **主界面**：毕业季校园 / 律所窗外场景，帧动画（云朵、落叶、光影）+ 主角待机循环。
- **角色**：主角做完整逐帧动画（走路/待机/情绪）；NPC 用立绘 + 表情差分切换，控制成本。
- **庭审场景**：法庭背景手绘 + 心证条 UI + 法官法槌动画。
- **音频**：柔和钢琴/管弦配乐，庭审紧张段落节奏加快；主界面循环 BGM。

## 11. 技术方案（Godot 4.x）

### 11.1 目录结构

按 AGENTS.md 约定：

```text
scenes/     # .tscn 场景（主界面、办公室、庭审、对话、结算）
scripts/    # .gd 脚本
assets/     # 美术、音频、字体（art/audio/fonts 子目录）
addons/     # 插件（Dialogic、GUT）
tests/      # GUT 自动化测试
docs/       # 设计文档（GDD 等）
```

### 11.2 Autoload（全局单例）

- `GameManager`：章节、周目、流程状态
- `StatsManager`：数值与违法值
- `EventManager`：事件池、触发与冷却
- `CardManager`：卡牌图鉴、卡组编辑
- `TrialManager`：庭审战斗状态、心证条
- `SaveManager`：多存档、结局图鉴、New Game+

### 11.3 数据驱动

- 事件、卡牌、案件、结局用自定义 `Resource`（.tres）或 JSON 定义，游戏逻辑与内容数据分离。
- 对话优先使用 Dialogic 插件。
- 每完成一个系统模块，用 GUT 补充测试；提交前跑 `godot --headless --import` 与测试。

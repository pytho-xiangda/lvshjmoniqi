# 设计与上下文共享

## 目的
让不同任务（NPC 性格设计、关卡/剧情设计、数值设计、卡牌设计等）共享同一份上下文。本项目所有任务共用同一个工作目录和同一个 git 仓库，因此**把产出写进仓库文件，并在 AGENTS.md 里登记**，即可实现跨任务共享。

## 约定

- 所有设计产出统一放 `docs/design/`，按子系统分目录。
- 仓库根目录的 `AGENTS.md` 登记关键产出的位置；每次会话开始时 Codex 自动读取 AGENTS.md，于是每个任务都知道去哪里找共享内容。
- 产出使用结构化格式（Markdown/JSON），便于其他任务直接读取和推导。

## 目录结构

```text
docs/design/
  characters/
    npc-<name>.md     # 每个 NPC 一份
    index.md          # NPC 总索引
  levels/
    level-<n>.md      # 关卡 / 剧情
  cards/              # 卡牌
  stats/              # 数值
```

## NPC 性格 Schema

每份 NPC 文件建议包含以下字段：

```markdown
# {{昵称}}
- id: npc_001
- 姓名 / 职业: 
- 性格标签: [固执, 圆滑]        # 2~4 个关键词
- 立场: 支持玩家 | 中立 | 对立
- 动机: 
- 弱点: 
- 与玩家关系: 

## 行为矩阵（性格 × 场景 → 可能剧情）
| 场景 | 可能反应 | 剧情走向 | 数值/卡牌影响 |
|------|---------|---------|--------------|
| 庭审质证 | | | |
| 私下谈判 | | | |
| 利益诱惑 | | | |
| 舆论压力 | | | |
| 危机/求助 | | | |
```

## 关卡 / 剧情任务如何使用

关卡设计任务先读取 `docs/design/characters/index.md` 和相关 NPC 文件，再把「NPC 性格」代入「关卡场景」，在行为矩阵的行×列位置上生成该 NPC 在该关卡可能出现的剧情分支。矩阵留空是正常的——由关卡任务针对具体场景填充。

## 示例（草稿）

```markdown
# 带教律师·老周
- id: npc_mentor
- 姓名/职业: 周建国 / 带教律师、合伙人
- 性格标签: [严谨, 护短, 等级观念]
- 立场: 支持玩家（但有保留）
- 动机: 律所声誉、把徒弟培养成可用之人
- 弱点: 好面子、对红圈所出身有偏见
- 与玩家关系: 师傅，初期决定案件分配

## 行为矩阵
| 场景 | 可能反应 | 剧情走向 |
|------|---------|---------|
| 庭审质证 | 不许你擅自质证，让你观战 | 学到「程序卡」 |
| 利益诱惑 | 告诫你"别碰底线"，但自己收礼 | 良知- / 违法值+ 的分岔 |
| 舆论压力 | 让你背锅平息媒体 | 口碑- / 人际-，可选反抗 |
```

## 需要共享的内容请在 AGENTS.md 登记

每新增一个可共享产出（人物表、卡牌表、数值表），就在 AGENTS.md 里补一行路径，保持每个任务都能一眼看到。
